# 백엔드 전체 컨벤션

이 문서는 백엔드 전 도메인에 공통으로 적용하는 기본 컨벤션이다.

## 1) 네이밍 규칙
- Java 클래스명: `UpperCamelCase` (예: `BoardService`)
- Java 변수/필드/메서드명: `lowerCamelCase` (예: `boardService`)
- DB 컬럼/테이블명: `snake_case`, 기본 단수형 사용 (예약어/특수 케이스 제외)

## 2) 계층 구조
- 기본 구조는 `Controller -> Service -> DAO` 3계층으로 구성한다.
- 도메인 간 기능 연동이 필요하면, 대상 도메인의 Service **인터페이스를 직접 사용**한다.

## 3) DTO / Command 규칙
- DTO는 **Controller 단에서만 사용**한다.
- Controller 요청 DTO는 `inner class` 형태로 관리한다.
- Service/DAO 계층 DTO 정책은 추후 확정 전까지 최소화한다.
- 조회 조건이 복잡해지면 `Command` 객체를 사용한다.

## 4) API 규칙
- RESTful API 규칙을 준수한다.
- Controller 반환은 공통 응답 포맷을 사용한다.
  - `ResponseEntity<ApiResponse<T>>`
- HTTP 상태코드는 의미에 맞게 사용한다. (예: 생성 `201 Created`, 조회 `200 OK`)

## 5) 도메인/에러 규칙
- 도메인 객체 생성은 `@Builder`를 사용하고, Builder로 생성한다.
- 에러 코드는 도메인별로 커스텀 `*ErrorCode` enum을 작성한다.
- 에러 코드는 짧고 명확하게 유지한다.
- 각 도메인은 전용 Exception 클래스(`*Exception`)를 작성하여 사용한다.
  - 모든 커스텀 예외는 `com.web.SearchWeb.config.exception.BusinessException`을 상속받는다.
  - 에러 코드 인터페이스: `com.web.SearchWeb.config.exception.ErrorCode`
  - 예시: `linkanalysis` 도메인 → `LinkAnalysisException`

## 6) Config 배치 규칙
- Config는 `config` 폴더 하위에 도메인 폴더를 만든 뒤 배치한다.
- 공통 프레임워크 관련 Config(예외, 응답 등)는 `config.exception`, `config.common` 등에 배치한다.
- 예시: 아이템 도메인 Config -> `config/item/ItemConfig.java`

## 7) 머지 기준
- 테스트가 있으면 테스트 통과 후 머지한다.
- 테스트 코드가 없더라도, 서버 실행(기동) 정상 확인 후 머지한다.

## 8) 커밋 규칙
- 커밋 계획서 및 커밋 메시지 작성 시 다음 스타일을 반드시 준수한다.
- **제목 형식**: `type(scope): 요약`을 유지한다. 기존 커밋 메시지 재작성 시 원 제목을 유지한다.
- **영역별 계층형 bullet**: 상위 bullet은 `- 영역:`으로 묶고, 하위 bullet은 공백 2칸 뒤 `- `로 시작한다. 변경 없는 영역은 생략한다.
  - 백엔드는 DB, Entity & DTO, Service, Controller & Error Handling, Test 등 실제 변경 영역으로 묶는다.
  - 프런트엔드는 UI Components, State & API, Accessibility, Test 등 실제 변경 역할에 맞는 그룹명을 사용한다.
  - 문서는 PRD, 기능 명세, 기술 설계, 문서 경로, PR Template, Commit Convention 등 문서 역할이나 변경 대상을 그룹명으로 사용한다.
- **파일명 명시**: 식별에 필요한 파일/컴포넌트·메서드명은 `이름: 설명` 형태로 명시하되, 모든 행 선두에 강제하지 않는다.
- **간결한 설명**: 하위 항목은 한 줄에 한 변경을 적는다. 핵심 오류 코드·컬럼·주요 메서드는 필요할 때 괄호로 보충한다. 이유·검증 결과·롤백·운영 승인·재실행 여부 등 메타 설명은 커밋 본문에서 제외하고 PR 또는 작업 기록에 둔다. 항목 수나 글자 수를 맞추려고 내용을 생략하거나 늘리지 않는다.
- **명사형 종결**: 추가·정의·적용·변경 등 명사형으로 마무리하고 줄 끝 마침표를 붙이지 않는다.
- **Test 작성**: 이 커밋에서 추가·수정한 테스트 코드와 대상만 적는다. 실행 결과·수동 HTTP 증거·미실행·미검증은 PR 또는 작업 기록에 구분하며, 미실행을 통과로 표시하지 않는다.
- **스타일 무결성**: 인공지능은 사용자의 명시적인 지시 없이 커밋 계획의 스타일이나 상세 수준을 임의로 변경하거나 요약해서는 안 된다.

### 범용 복사 템플릿
아래 대괄호는 실제 변경으로 교체하고, 해당 없는 그룹/항목은 제거한다. 그룹 이름과 수는 실제 역할에 맞게 조정한다.

```text
type(scope): 요약

- [영역/역할]:
  - [한 변경과 필요한 식별자] 추가
- [다른 영역/역할]:
  - [한 변경] 수정
- Test:
  - [추가·수정한 테스트 코드의 대상] 테스트 추가
```

### C2 작성 예시
폴더 고정 변경의 영역별 메시지 예시다. Test는 추가된 테스트 코드를 가리키며 실행 결과는 별도 기록한다.

```text
feat(folder): 폴더 고정(Pinned) 저장·조회 API 및 요청 오류 응답 정비

- DB:
  - member_folder에 is_pinned 컬럼 및 인덱스 추가 (증분 마이그레이션 스크립트 포함)
- Entity & DTO:
  - MemberFolder에 pinned 필드 매핑 및 생성/수정/조회 DTO 확장
- Service:
  - 폴더 생성 시 고정 여부 동시 저장 지원 (하위 폴더 지정 시 F009)
  - setPinned: 비관적 락 기반 소유권·타입(CUSTOM/UNORGANIZED) 검증 및 멱등 갱신
  - listPinned: 고정된 루트 폴더 목록 필터링 조회
- Controller & Error Handling:
  - 고정 목록 조회(GET) 및 고정 상태 변경(PATCH) 엔드포인트 추가
  - 바인딩/JSON 파싱 예외를 전역 500 대신 400 F010으로 처리하는 컨트롤러 전용 핸들러 추가
  - FOLDER_FORBIDDEN 오타 정정(Foo3 -> F003) 및 F009/F010 신규 오류 코드 정의
- Test:
  - 서비스·컨트롤러 단위 테스트 및 HTTP 입력 검증·인가 회귀 테스트 추가
```
