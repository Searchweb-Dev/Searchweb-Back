# SearchWeb 계획 문서 안내

이 README는 문서 탐색 안내다. 작업 진행·검증 결과·승인 원문은 별도 작업 관리 도구에서 관리하며 여기서 이중 관리하지 않는다.

## 문서 역할과 읽는 순서

1. [전체 PRD](./Searchweb_PRD.md): 목표·사용자·전체 범위·간결한 기능 목록·우선순위의 기준. 파일명은 사용자 피드백에 따라 변경했으며 Pinned 외 제품 요구는 유지한다.
2. [Pinned 선택 출처 명세](./features/pinned-folders/spec-v2.md): 선택 당시 FR-3.6 정책·흐름·요구·권한·예외·수용 기준과 미결 질문. 내부 기준 spec.md는 게시 제외한다. 원본 보존 해시와 참조만 보완한 게시본 해시는 구분하며 선택 취소를 뜻하지 않는다. 상세는 PRD에 중복 복사하지 않는다.
3. [Pinned 기술 설계](./features/pinned-folders/technical-design.md): API·DB·캐시 및 후속 승인 결정. 검토 현황과 3.5절의 단일 노출·최대 2행 결정을 선택 출처 명세와 함께 읽는다. 설계 승인과 제품 테스트 완료·머지·배포 승인은 구분한다.

Pinned 외 기존 계획서도 아래 기능별 경로로 이동했다. 기존 계획서는 요구·설계·실행 제안이 섞인 원래 자료이며, 링크한다고 확정 명세·실제 구현·승인된 실행 계획이 되는 것은 아니다.

## 점진적 정리 원칙

- 합의된 문서 경로 재구성을 반영한다. 아래 기존 자료는 참고 문서이며 추가 archive/legacy 이동이나 임의 삭제는 하지 않는다.
- 기능 상세는 `features/<기능>/spec.md`, 구현 방법은 별도 승인 후 `technical-design.md`로 구분한다. 기존 혼합 문서의 파일명만 바꿔 확정 명세로 취급하지 않는다.
- 요구·AC·질문 ID와 원문 및 이전/현재 경로의 대응을 보존한다. 문서별 버전·변경 이력·승인 경계를 확인한다.
- 문서 구조 정리 완료는 내용 최종 승인이나 설계·구현·머지·배포 승인이 아니다.
