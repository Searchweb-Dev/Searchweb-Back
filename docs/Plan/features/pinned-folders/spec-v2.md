## 목적과 범위

Pinned는 로그인 사용자의 폴더 *바로가기*다. My Folder의 원본 폴더·ID·북마크를 그대로 사용하며 이동·복제하지 않는다.
- **포함:** 일반 루트 폴더·미분류(`UNORGANIZED`)의 생성 시 고정 선택, 기존 폴더 고정·해제, 계정별 서버 저장과 표시·권한·실패 처리. 가상 전체 링크는 대상이 아니다.
- **제외:** 아이콘·색상, 드래그/일괄 고정, 하위 폴더 탐색, 검색 전면 개편·별도 글로벌 검색, 신규 이름순/독립 고정 정렬, 별도 이름 동기화 및 신규 분석·로깅. 기존 폴더 삭제 시 북마크 처리 정책을 변경하지 않는다.
- **기존 기능 영향:** 폴더 생성·조회·이름 변경·삭제(FR-3.1~3.4), 폴더/링크 선택(FR-3.5, FR-2.3, FR-6.3), 검색·필터·정렬(FR-6), 기존 링크 저장·분석 호출을 회귀 검증한다. 임시 상단 폴더·`SaveLinkDialog`의 `pinnedFolderId`를 사용자의 영속 고정 의사로 간주하지 않는다. 기존 NFR을 유지하며 새 성능 수치나 개수 상한을 설정하지 않는다.

## 사용자 흐름

1. **생성:** 진입(기본 OFF) → ON/OFF 선택 후 폴더와 함께 저장 → 성공 시 My Folder와 Pinned에 선택값대로 표시(OFF면 My Folder만 표시). **부분 성공은 실패 처리한다.**
2. **고정·해제:** 메뉴/카드에서 조작 → 클릭 즉시 버튼 비활성화+스피너 → 저장 실패가 확인되면 이전 상태로 롤백+에러 토스트 → 성공 시 바로가기 반영 및 마지막 해제 시 안내 카드 표시.
3. **재방문·동기화:** 서버 저장값만 조회하여 동일 폴더 ID로 열기 → 원본 이름 변경/삭제 결과가 두 영역에 일치. 별도 이름 동기화 기능은 추가하지 않는다.

통신 결과가 불명확한 경우에는 확정 실패로 단정하지 않고 PIN-12와 Q-03의 재확인 기준을 따른다.

## 상세 요구와 수용 기준

아래 PIN-01~12가 이번 기능의 요구이며, AC는 *향후 검증할 기대 결과*다. 테스트 통과 기록이 아니다. 표의 각 AC는 `<br>`로 줄을 나눈다. 이번 사용자 제공 결정으로 바뀐 AC는 아래에 반영했고, 이외 기존 요구·AC ID는 유지한다.

## 상태·권한·실패 시 확인할 접점

- **조회 중/빈 상태:** 아직 모르는 서버 값을 확정된 빈 목록이나 성공으로 오인시키지 않는다(PIN-05/08). 고정 0개가 확인되면 합의한 안내 카드를 보여준다.
- **저장 중/실패:** 클릭 즉시 버튼 비활성화·스피너(PIN-11). 확정 실패 시 화면 롤백·에러 토스트(PIN-12). 결과 불명확 시 재확인·재시도 후 서버와 일치시킨다. 인증 실패도 성공으로 표시하지 않는다.
- **인증 만료·타인 소유·삭제 대상:** 서버가 허가되지 않은 변경을 거부하고 타인의 고정 항목을 반환하지 않는다(PIN-09/10). 기존 삭제 권한과 정책을 유지한다.

| Q-06 검증 | 백엔드 JUnit + 프런트 Jest 자동화 테스트, 브라우저 동작 시나리오 실행과 캡처/로그 증거. 별도 QA 인력은 두지 않음 | 구현자와 분리된 검증을 *누가 어떤 방식으로* 수행할지, 실제 프런트 테스트 도구 적합성·실행 환경·증거 형식. 자동화 테스트만으로 독립 검증이 완료됐다고 하지 않음 |
| Q-07 머지/배포 | 로컬 브랜치에서 개발·테스트를 완료한 뒤 사용자 최종 승인 전까지 원격 push·머지 금지 | ‘테스트 100%’의 통과 범위·독립 검증 게이트, 최신 원격 기준·배포 트리거·복구 경로. 이 문서만으로 코드 작성·push·머지·배포를 허가하지 않음 |

이전 질문의 원문과 영향·위험은 게시 제외된 기존 spec의 Q-01~07 원문(내부 승인 기록) 및 Kanban `t_83c71a87` 댓글 #13에 보존한다. 미결 세부사항은 추측으로 확정하지 않고 후속 승인된 설계·검증 단계에서 확인한다.
